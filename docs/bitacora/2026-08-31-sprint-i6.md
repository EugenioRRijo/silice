## Sesión I6.3 — Predicción de precio (UC‑07) — commit `feat(ml)`

- **Compuerta G2 CRUZADA**: `tecnica_para` es la tabla de NORMAS.md §8.1 hecha código; el conteo
  real sobre el catálogo sembrado (civil = 5, telecom/industrial/sistemas = 0, todos < 50) dicta
  **sistema de reglas con análisis de sensibilidad, declarado como limitación**. La evidencia
  vive en `docs/resultados_ml.md` (generado, reproducible) y en `tests/unit/test_prediccion.py`.
- **`ml/prediction/reglas.py`**: regla declarada (PU estimado = PU base × (1 + media de las
  variaciones del histórico)), rango de sensibilidad (variación mínima y máxima), métricas
  MAPE/RMSE/R² en `Decimal` (raíz con `Decimal.sqrt()`), y `contrastar_aace` (RF‑29): `Hallazgo`
  de severidad ADVERTENCIA del contrato cuando la desviación sale de la clase 3 de AACE
  (−20 % / +30 %, límites inclusivos, RP 18R‑97).
- **`scripts/generar_resultados_ml.py`** evalúa el caso UC‑02 de la línea base sobre una base en
  memoria — el motor de costos es la verdad de terreno — y escribe `docs/resultados_ml.md`:
  **MAPE 12,46 %, RMSE 5,10 USD, R² 0,9974, 0 hallazgos AACE**. El MAPE alto es la limitación en
  acción: la regla usa un índice agregado y no conoce la composición; el documento lo declara.

## Decisiones

| Decisión | Motivo |
|---|---|
| Meta del sprint antes que el código, reutilizando `meta_alpha._evaluar` parametrizado | Principio 5 de NORMAS.md aplicado al nivel de sprint; DRY: una sola maquinaria de evaluación |
| La advertencia normativa de RF‑27 es la de **rango observado** (core); el veredicto del bosque es enriquecimiento opcional (API, import perezoso) | El criterio del ERS habla de «rango observado»; `core` no puede importar `ml` (arquitectura), y sin el extra `ml` la API debe funcionar igual |
| `MINIMO_OBSERVADO_PARA_ADVERTIR = 2` en el rango (vs 8 del bosque) | Un punto no define comportamiento; dos ya dan un rango real. El bosque exige más porque es un juicio estadístico |
| La regla de predicción NO conoce la composición del APU | Si la conociera, recalcularía lo mismo que `core.costing` (circular, error cero, métrica vacía); su error frente al motor es exactamente lo que las métricas miden |
| R² presentado a 4 decimales en el informe | A dos, 0,9974 se presenta «1.00»: engaña |
| `scripts/generar_resultados_ml.py` importa `tests.fixtures` | Precedente de `scripts/seed.py`: la línea base vive una sola vez (NORMAS.md §2, DRY) |

## Hallazgos

1. **UC‑06 en la UI queda diferido**: «al crear un APU, proponer el rendimiento» presupone un
   flujo de composición manual de APU que ninguna pantalla ofrece todavía — la misma familia del
   hallazgo RF‑16 (I2). La API es el front del caso de uso (Swagger, decisión F.1); la página
   llegará con el flujo de creación de partidas/APU (G0 o Fase 6).
2. **`EnterWorktree` falló al crear por un problema de mayúsculas de ruta en Windows** (`c:` vs
   `C:`): el worktree quedó creado y la entrada funcionó por `path`. Anotado por si reaparece.
3. La escala de `decision_function` dependiente del tamaño de muestra (hallazgo de I6.1) no
   estorbó aquí: el enriquecimiento del bosque en la API se abstiene con menos de 8 observaciones.
