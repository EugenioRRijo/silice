# Bitácora — Sesión F.3: manuales de usuario y técnico

**Fecha:** 2026‑08‑31 · **Rama:** `inc/F3-manuales` (fusionada a `main` con `--no-ff`) ·
**Base:** `c2bf429` (cierre UC‑08) · **Sesión del PLAN:** F.3 (Fase 6, **última del PLAN**),
pedida por el usuario junto con el cierre de UC‑08.

## Qué se hizo

1. **[docs/manual_usuario.md](../manual_usuario.md)**: operación completa para el proyectista sin
   asumir que sabe programar — instalación (`uv sync`, RNF‑07), siembra, arranque de UI y API,
   las siete pantallas mapeadas a sus UC, los flujos de UC‑01/02/03/06/07/08, cómo leer el
   informe de auditoría (que se genera siempre), exportación, tabla de archivos de muestra y
   problemas frecuentes. UC‑08 se documenta como es: por la API de `core.budget`, con el ejemplo
   mínimo de código y la nota de que no tiene página propia.
2. **[docs/manual_tecnico.md](../manual_tecnico.md)**: la regla que gobierna todo (núcleo cerrado,
   con sus dos guardias automáticas), entorno y convenciones, mapa del código, **la guía paso a
   paso para escribir un adaptador de dominio nuevo** (contrato completo, ejemplo de código,
   pruebas primero, las dos listas de despacho opcionales en UI/API) con sus límites dichos
   honestamente (un quinto dominio exige ampliar la enumeración `Dominio`: decisión de
   gobernanza, se registra en bitácora), cómo añadir una regla de verificación (tupla `REGLAS`),
   persistencia, `ml/` y compuertas, scripts reproducibles y las decisiones no obvias (la UI no
   consume la API por HTTP; montos como texto; la línea base tiene una sola copia).
3. `docs/README.md`: los manuales pasan de pendientes a completos — **ninguna fila del índice de
   documentación queda pendiente**.

## Decisiones

| Decisión | Motivo |
|---|---|
| El manual técnico no repite la arquitectura ni el modelo de datos: los enlaza y recorre | DRY documental (NORMAS.md §2.1); un manual que copia las vistas 4+1 se desactualiza a la primera sesión |
| La guía del adaptador incluye el contrato **completo** en el propio manual | Es tan pequeño (una clase, un método) que citarlo entero demuestra el aporte mejor que describirlo; la fuente sigue siendo `core/contracts/adaptador.py` |
| El límite del quinto dominio se declara en la guía, no se esconde | La extensibilidad probada es «adaptador nuevo sin tocar `core/`»; ampliar la enumeración `Dominio` es un cambio de contrato y el manual lo dice con su procedimiento (bitácora + gobernanza) |
| UC‑08 documentado por API de `core` con ejemplo ejecutable | Documentar una pantalla que no existe sería mentir; el hallazgo de cablearla sigue abierto (bitácora del cierre UC‑08) |
